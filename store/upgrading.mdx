Keep your installed providers up to date or remove them when no longer needed.

## Prerequisites

- Install the CLI: see [Installation](/cli/installation)
- Authenticate: `pragma auth login`
- Verify context: `pragma config current-context`

## Checking Installed Versions

View your installed providers, their state and the version each serves:

```bash
pragma providers list --installed
```

Compare with the versions a provider has published:

```bash
pragma providers versions pragmatiks/qdrant
```

## Upgrading a Provider

### Upgrade to Latest

```bash
pragma providers upgrade pragmatiks/qdrant
```

```text
Upgrading: pragmatiks/qdrant -> latest

Upgrade pragmatiks/qdrant to latest? [y/N]: y
Upgrade queued: pragmatiks/qdrant -> v1.2.0
Follow it with: pragma providers history pragmatiks/qdrant
```

### Upgrade to a Specific Version

```bash
pragma providers upgrade pragmatiks/qdrant --version 1.2.0
```

### Downgrade

```bash
pragma providers downgrade pragmatiks/qdrant --version 1.1.0
```

### Skip Confirmation

```bash
pragma providers upgrade pragmatiks/qdrant -y
```

### What Happens During an Upgrade

An upgrade or downgrade is queued, then starts the target version alongside the installed one, like an install (see [Installation Lifecycle](/store/installing#installation-lifecycle)). It ends **Running** on the target version, or **Failed** if it does not finish in time. The installed version keeps serving your resources until the new one runs. Follow it with:

```bash
pragma providers history pragmatiks/qdrant
```

If the target version cannot start, the provider returns to **Running** on the installed version, which keeps serving your resources. `pragma providers list --installed` shows the failure message, such as:

```text
Upgrading pragmatiks/qdrant to 1.2.0 failed: The provider worker stopped before it could serve. The installed version keeps serving; publish a new version and upgrade to it.
```

The history records the failure under the installed version, and its message names the target version that failed. To try again, run the upgrade or downgrade again once the cause is fixed.

Install, upgrade, downgrade and uninstall affect only the provider you name: your organization's other providers keep serving without a restart.

An upgrade or downgrade is refused while another operation on the provider is running; wait for it to finish, then run the command again. A failed installation cannot be downgraded; install the version you want instead:

```bash
pragma providers install pragmatiks/qdrant --version 1.1.0
```

## Compatibility Checks

Pragmatiks refuses an install, upgrade, downgrade or uninstall that would break something you run. The refusal says what to do, and nothing changes until you do it.

### Providers That Embed Other Providers

A provider can embed other providers. It can be installed only when every provider it embeds, directly or through another provider, is installed. The refusal names each missing provider with the command and version to install:

```text
acme/outer embeds acme/inner and acme/middle, which are not installed. Run: pragma providers install acme/inner --version 1.0.0; pragma providers install acme/middle --version 1.2.0
```

### Changes That Would Break an Embedding Provider

An install, upgrade or downgrade is refused when it would break an installed provider that embeds another. This happens in two cases.

An upgrade of the embedded provider drops or changes outputs, or configuration fields, that an embedding provider reads:

```text
Upgrading acme/p to 2.0.0 drops or changes outputs acme/c reads: embedded.imported_packages. Upgrade acme/c to a version built against acme/p 2.0.0, or keep the installed version.
```

An embedding provider expects outputs the installed provider does not provide:

```text
acme/c 1.1.0 reads outputs installed acme/p 1.0.0 does not provide: embedded.zone. Upgrade acme/p first, or upgrade acme/c to a version built against acme/p 1.0.0. Run: pragma providers upgrade acme/p --version 1.1.0
```

Adding outputs never breaks an embedding provider.

### Resource Types That Would Disappear

A version change is refused when the new version drops a resource type that your resources still use. Resources in draft do not count. The refusal names the resources:

```text
Upgrading acme/p to 4.0.0 drops resource type embedded, which 2 resources use: acme/p/embedded/a, acme/p/embedded/b. Delete them first, or keep the installed version.
```

### Applying Resources

Applying a resource is refused while its provider is being uninstalled:

```text
provider acme/p is being uninstalled. Wait for the uninstall to finish, then install it again before applying resources of its types.
```

It is also refused when the installed version does not define the resource type:

```text
pragmatiks/gcp 8.0.0 does not define resource type cloudsql/user. Upgrade or downgrade pragmatiks/gcp to a version that does, or delete the resource.
```

Resources that a provider creates for you belong to the provider that defines their type, so that provider must be installed too. See [Resource Lifecycle](/building-providers/lifecycle).

## Uninstalling a Provider

### Basic Uninstall

```bash
pragma providers uninstall pragmatiks/qdrant
```

```text
Provider: pragmatiks/qdrant

Are you sure you want to UNINSTALL provider? [y/N]: y
Uninstall queued: pragmatiks/qdrant
Follow it with: pragma providers history pragmatiks/qdrant
```

While it is removed, the provider shows **Uninstalling** in `pragma providers list --installed`. Its history stays available for 30 days.

<Warning>
An uninstall is refused while an installed provider embeds this one. The refusal lists them with the command to uninstall each:

```text
acme/c and acme/d depend on acme/p. Run: pragma providers uninstall acme/c; pragma providers uninstall acme/d
```
</Warning>

<Warning>
If the provider has active resources, the uninstall fails. Delete the resources first, or use `--cascade`.
</Warning>

### Cascade Delete

Uninstall the provider and delete all resources it manages:

```bash
pragma providers uninstall pragmatiks/qdrant --cascade
```

The `--cascade` flag deletes every resource created by the provider before removing the provider itself.

### Skip Confirmation

```bash
pragma providers uninstall pragmatiks/qdrant --cascade -y
```
