## Authentication

### "Not authenticated" error

Run `pragma auth login` to authenticate.

### Token expired

Re-authenticate with `pragma auth login`.

## Resources

### Resource stuck in PENDING

Check if dependencies are in `ready` state:

```bash
pragma resources describe <organization>/<provider>/<resource>/<name>
```

A resource with unready dependencies waits in `waiting`, not `pending`, until all dependencies are ready; `describe` lists each one under `Blocked by:`.

If all dependencies are `ready` but the resource is still `pending`, re-apply it:

```bash
pragma resources apply resource.yaml
```

### Resource stuck in PROCESSING

Resources in `processing` state are being handled by a provider. If a resource stays in this state longer than expected:

1. **Wait** — An operation has 20 minutes to finish. After that the resource moves to `failed` with the message `Resource <id> did not finish within 1200 seconds. Apply again to retry it, or deactivate the resource to discard it.`
2. **Apply a changed configuration** — Applying while a resource is `processing` queues the new configuration. It is applied when the running operation ends, and the resource shows `processing (apply queued)` until then.
3. **Re-apply after a failure** — Start a new attempt:

```bash
pragma resources apply resource.yaml
```

### Resource failed

Check the error message:

```bash
pragma resources describe <organization>/<provider>/<resource>/<name>
```

Fix the configuration and re-apply:

```bash
pragma resources apply fixed-resource.yaml
```

### Resource not updating after dependency change

If a resource isn't updating after its dependency changed, check the `resolved_config`:

```bash
pragma resources describe <organization>/<provider>/<resource>/<name> -o json
```

Compare `config` (your declaration) with `resolved_config` (what the provider received). If `resolved_config` still shows old values, the dependency change may not have propagated yet — verify the dependency is in `ready` state.

### Deletion not working

If a resource won't delete:

- **Resource in `failed` state** — Failed resources can still be deleted. Check for errors:

```bash
pragma resources describe <organization>/<provider>/<resource>/<name>
```

- **Resource in `processing` state** — Wait for the current operation to complete, then try deleting again.

- **Delete from YAML** — Use the file-based delete to remove multiple resources:

```bash
pragma resources delete -f resources.yaml
```

## File Uploads

### File upload fails

When using `@path` syntax for `pragma/file` resources:

- Verify the file exists at the specified path (relative to the YAML file's directory)
- Ensure `content_type` is specified in the config — it's required for file uploads
- Check the file size is within the platform's limits

```yaml
provider: pragma
resource: file
name: my-document
config:
  content: "@./document.pdf"
  content_type: "application/pdf"
```

### File resource stuck in FAILED

If a `pragma/file` resource fails with "File content not uploaded":

1. The file resource was created but the file content wasn't uploaded yet
2. Re-apply the resource with the `@path` syntax to trigger the upload:

```bash
pragma resources apply file-resource.yaml
```

## Provider Development

### Publish failures

Run `pragma providers versions <org>/<provider>` to see a failed version's message. The admission failures you can fix:

| Category | Message | Fix |
|----------|---------|-----|
| `wheel_refused` | The uploaded wheel does not match its declaration or could not be read. Rebuild the wheel and publish it again. | Rebuild and publish again |
| `wheel_too_large` | The wheel expands to more than 256 MiB. Reduce its size and publish it again. | Shrink the wheel |
| `digest_mismatch` | The uploaded wheel is not the wheel this publish declared. Run 'pragma providers publish' again. | Publish again |
| `wheel_lost` | The uploaded wheel of `<provider>` `<version>` was lost before it was published. Run 'pragma providers publish' again. | Publish again |

Upload errors the CLI prints, each followed by `To publish it again, run: pragma providers publish --wheel <path>` (exit 1):

- **Expired address**: "The wheel upload address expired before storage received the whole wheel (HTTP `<status>` `<code>`, storage request `<id>`)." The whole wheel must arrive before the upload address expires; publish again for a fresh one.
- **Refused upload**: "Storage refused the wheel upload (HTTP `<status>` `<code>`, storage request `<id>`)."

Before anything is declared, a renamed copy that cannot be written prints "Could not write the renamed copy of the wheel: `<reason>`. Free space in the temporary directory or point TMPDIR elsewhere, then publish again." (exit 1).

When the watch ends before the version settles, publish exits 3 with "Admission of `<name>` `<version>` has not finished" and the command to keep waiting, `pragma providers wait <name> <version> --operation <operation-id>`.

### No pyproject.toml in the project directory

`pragma providers publish` builds the wheel from the project directory. Run it from the provider directory, or pass the directory:

```bash
pragma providers publish ./mycompany-provider
```

A missing project directory, or one without `pyproject.toml`, exits 2.
