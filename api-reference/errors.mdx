The API uses standard HTTP status codes and returns detailed error information in JSON format.

## HTTP Status Codes

| Code | Meaning | When it occurs |
|------|---------|----------------|
| `200` | Success | Request completed successfully |
| `201` | Created | Resource created successfully |
| `202` | Accepted | Request accepted for async processing |
| `204` | No Content | Successful deletion (no response body) |
| `400` | Bad Request | Invalid request parameters |
| `401` | Unauthorized | Missing or invalid authentication |
| `403` | Forbidden | Authenticated but not authorized |
| `404` | Not Found | Resource does not exist |
| `409` | Conflict | Invalid state transition or concurrent modification |
| `410` | Gone | Your organization is being deactivated or has been deleted |
| `422` | Validation Error | Request body failed validation |
| `500` | Server Error | Internal server error |
| `503` | Service Unavailable | Your organization is not ready yet; retry later |

## Error Response Format

Every error response has one envelope: a `detail` member. `detail` is either the message itself:

```json
{
  "detail": "Human-readable error message"
}
```

or an object carrying the `message`, plus a stable machine-readable `error` code when the refusal has one, and any fields specific to the refusal:

```json
{
  "detail": {
    "error": "organization_last_admin",
    "message": "Your organization must keep at least one admin. Promote another member to admin first."
  }
}
```

Read the code from `detail.error`; no error field sits at the top level of the body.

Validation errors include additional location information:

```json
{
  "detail": [
    {
      "loc": ["body", "name"],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}
```

## Common Errors

### Authentication Errors (401)

Missing or expired token:

```json
{
  "detail": "Not authenticated"
}
```

**Solution**: Re-authenticate with `pragma auth login`.

### Not Found Errors (404)

Resource or build job does not exist:

```json
{
  "detail": "Resource not found: postgres/database/my-db"
}
```

**Solution**: Verify the resource ID exists in your namespace.

### Conflict Errors (409)

#### Invalid Lifecycle Transition

A change the resource's current state does not allow. The `detail` object names the current state and the state the request asked for, and its `message` says what to do instead:

```json
{
  "detail": {
    "message": "Resource acme/postgres/database/my-db is ready, so it cannot be saved as a draft. Deactivate it instead: pragma --project my-project resources deactivate acme/postgres/database/my-db",
    "current_state": "ready",
    "target_state": "draft"
  }
}
```

The messages you can meet:

| Request | Message |
|---------|---------|
| Save as a draft a resource that is `ready`, `waiting` or `failed` with provisioned infrastructure | `Resource <id> is <state>, so it cannot be saved as a draft. Deactivate it instead: pragma --project <project> resources deactivate <id>` |
| Save as a draft a resource that is `processing` | `Resource <id> is processing, so it cannot be saved as a draft. Once its operation ends, deactivate it: pragma --project <project> resources deactivate <id>` |
| Save as a draft a `failed` resource with nothing provisioned | `Resource <id> is failed and not provisioned, so it cannot be saved as a draft. Delete it to take it out of the project: pragma --project <project> resources delete <id>` |
| Apply a resource that is `deleting` | `Resource <id> is deleting, so it cannot be applied now. Once its operation ends, apply it again.` |

**Solution**: Run the command the message names. A resource that is not a draft leaves service through `deactivate`, which returns it to `draft`; a failed resource with nothing provisioned leaves the project through `delete`.

#### Write Contention

A change that conflicted with other changes saved at the same time and was not saved. The `detail` object carries the message and a machine-readable `reason`:

```json
{
  "detail": {
    "message": "This change conflicted with other changes saved at the same time and was not saved. Try again.",
    "reason": "write_contention"
  }
}
```

**Solution**: Send the request again.

### Validation Errors (422)

#### Missing Required Fields

```json
{
  "detail": [
    {
      "loc": ["body", "provider"],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}
```

**Solution**: Include all required fields in your request.

#### Dependency Validation Failed

Dependencies don't exist or aren't ready:

```json
{
  "detail": "Dependency validation failed: postgres/database/missing-db does not exist"
}
```

**Solution**: Ensure all dependencies exist and are in READY state.

#### Field Reference Resolution Failed

A field reference points to a non-existent output:

```json
{
  "detail": "Field reference failed: postgres/database/my-db does not have output 'connection_string'"
}
```

**Solution**: Verify the referenced resource exists and has the expected outputs.

### Build Errors (400/404)

#### Build Job Not Found

```json
{
  "detail": "Build job not found: build-abc123"
}
```

**Solution**: Verify the job name from the push response.

#### Build Creation Failed

```json
{
  "detail": "Failed to create build job"
}
```

**Solution**: Check that the provider code archive is valid.

### Organization State Errors

A request your organization's state refuses carries its code in `detail.error`:

| Status | `error` | Meaning |
|--------|---------|---------|
| `503` | `organization_bootstrapping` | Your organization is being set up. Retry later. |
| `503` | `organization_details_unavailable` | Your organization's details are temporarily unavailable. Retry later. |
| `503` | `membership_details_unavailable` | Membership details are temporarily unavailable. Retry later. |
| `503` | `organization_versions_unsettled` | Provider versions of your organization are still being published. Retry later. |
| `503` | `staging_unavailable` | The wheel upload address could not be prepared. Publish the same wheel again. |
| `503` | `organization_bootstrap_failed` | Your organization could not be set up. Contact support at support@pragmatiks.io. |
| `410` | `organization_deactivating` | Your organization is being deactivated and is no longer available. |
| `410` | `organization_deleted` | Your organization has been deleted and is no longer available. |
| `409` | `organization_deleting` | Your organization is being deleted. Deletion cannot be cancelled. |
| `409` | `organization_slug_taken` | The organization slug is already taken. Choose another. |
| `409` | `organization_last_admin` | Your organization must keep at least one admin. Promote another member first. |
| `409` | `account_last_admin` | You are the last admin of the organizations the message names. Promote another member, or delete the organization first. |

### Retry Later (503)

A `503` you can retry carries the code, the message and `retry_after`, the number of seconds to wait, inside `detail`. The `Retry-After` header carries the same delay:

```json
{
  "detail": {
    "error": "organization_bootstrapping",
    "message": "Your organization is being set up. Please try again in a moment.",
    "retry_after": 5
  }
}
```

**Solution**: Wait `retry_after` seconds, then send the request again. `organization_bootstrap_failed` carries no `retry_after`: retrying does not help.

## Lifecycle State Reference

Understanding lifecycle states helps interpret errors:

| State | Description | Can Modify? |
|-------|-------------|-------------|
| `draft` | Initial state, not yet committed | Yes |
| `pending` | Committed, waiting to be processed | No |
| `processing` | Currently being handled by a provider | No |
| `ready` | Successfully processed | Yes |
| `failed` | Processing failed, error recorded | Yes |

## Best Practices

1. **Check response status codes** before parsing the body
2. **Retry with backoff** for 5xx errors
3. **Don't retry** 4xx errors without fixing the request
4. **Poll status endpoints** for async operations (builds, installations)
5. **Log correlation IDs** from responses for debugging
