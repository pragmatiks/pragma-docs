## Login

```bash
pragma auth login
```

Opens your browser for authentication.

### Log in without a browser

For automation where no browser is available, pipe a session token to `--with-token`:

```bash
echo "$SESSION_TOKEN" | pragma auth login --with-token
```

The command reads one session token from stdin, never from an argument, checks it against the API, and saves it for the context. It cannot be combined with `--org`, since the token already identifies its organization. Nothing is saved when stdin is a terminal, empty, or holds more than one value, or when the token is expired or refused.

An API key is not a session token. Pass an API key per command with `--token` or the `PRAGMA_AUTH_TOKEN` environment variable instead. See [API keys](/cli/api-keys).

pragma auth whoami

pragma auth logout

## Contexts

Contexts allow you to switch between different Pragmatiks environments—for example, development and production—each with its own API endpoint and credentials.

Each context stores:
- **API URL** - The endpoint for that environment
- **Authentication token** - Your credentials for that environment

This is useful when you need to work with multiple deployments or test against a local development server.

<Note>
You can override the current context for a single command using the `--context` / `-c` flag, or set the `PRAGMA_CONTEXT` environment variable.
</Note>

### List Contexts

```bash
pragma config get-contexts
```

### Switch Context

```bash
pragma config use-context production
```

### Create Context

```bash
pragma config set-context staging --api-url <url>
```

### Delete Context

```bash
pragma config delete-context staging
```
