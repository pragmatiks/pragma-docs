## Apply

Create or update resources from YAML (starts provisioning immediately by default):

```bash
pragma resources apply myresource.yaml
```

Apply multiple files:

```bash
pragma resources apply file1.yaml file2.yaml
```

Create in draft state (skip provisioning):

```bash
pragma resources apply --draft myresource.yaml
```

<Note>
Resources are deployed by default when you apply them. Use `--draft` to save a resource configuration without triggering provisioning. Only a new resource or one that is already a draft can be saved as a draft; for any other resource the command fails and the error says how to recover it.
</Note>

### File References

For `pragma/secret` resources, use `@path` syntax to inline file contents:

```yaml
provider: pragma
resource: secret
name: gcp-credentials
config:
  data:
    service_account_key: "@./service-account.json"
```

For `pragma/file` resources, use `@path` in the `content` field to upload a file:

```yaml
provider: pragma
resource: file
name: training-data
config:
  content: "@./data/training-set.jsonl"
  content_type: "application/jsonl"
```

The file is uploaded to Pragmatiks storage, and the resource outputs include a URL for downloading it.

## List

```bash
pragma resources list
```

Output as JSON for scripting:

```bash
pragma resources list --output json
```

Filter by provider:

```bash
pragma resources list --provider gcp
```

Filter by resource type:

```bash
pragma resources list --resource warehouse
```

Filter by tags:

```bash
pragma resources list --tag env:production
```

## Schemas

List available resource schemas from installed providers:

```bash
pragma resources schemas
```

Filter by provider:

```bash
pragma resources schemas --provider gcp
```

## Get

Get resources by type:

```bash
pragma resources get pragmatiks/gcp/storage
```

Get a specific resource:

```bash
pragma resources get pragmatiks/gcp/storage/my-bucket
```

## Describe

Get detailed information about a resource, including its state, health, full configuration, resolved config, and outputs:

```bash
pragma resources describe pragmatiks/gcp/storage/my-bucket
```

While an operation is running, the output includes an `Operation` row such as `update <operation-id>`. A resource that received a new configuration while processing shows the State `processing (apply queued)`.

The `Health` row shows the resource's health: `healthy`, `blocked`, `failed`, or `degraded` followed by each failed dependency, for example `degraded — pragmatiks/pragma/secret/api-key failed`. A waiting resource also lists what it waits for under `Blocked by:`, each with the command that shows it:

```text
Blocked by:
  pragmatiks/pragma/secret/api-key — Waiting for pragmatiks/pragma/secret/api-key to be ready.
    pragma --project my-project resources describe pragmatiks/pragma/secret/api-key
```

See [Health](/concepts/resources#health) for what each value means.

Output as JSON to inspect `resolved_config` for dependency debugging:

```bash
pragma resources describe pragmatiks/agno/agent/my-agent -o json
```

## Tags

Manage tags on existing resources:

```bash
# List tags
pragma resources tags list pragmatiks/gcp/storage/my-bucket

# Add tags
pragma resources tags add pragmatiks/gcp/storage/my-bucket --tag env:prod --tag cost-center:123

# Remove tags
pragma resources tags remove pragmatiks/gcp/storage/my-bucket --tag env:prod
```

## Deactivate

Deactivate a resource: its provider tears down the external object, and the resource returns to `draft`, ready to be applied again:

```bash
pragma resources deactivate pragmatiks/pragma/secret/api-key
```

Preview what a deactivate reaches without changing anything:

```bash
pragma resources deactivate --dry-run pragmatiks/pragma/secret/api-key
```

```text
Dry run — pragmatiks/pragma/secret/api-key was not deactivated.
Resources this reaches:
  pragmatiks/pragma/secret/api-key — torn down
  pragmatiks/agno/anthropic-model/claude — moved to waiting until its dependency returns
```

Each dependent moves to `waiting` without a call to its provider, and recovers by itself once the resource is applied again and ready. Add `--wait` to block until the teardown finishes (`--wait-timeout <seconds>`, `0` waits forever), or `-f <file>` to deactivate every resource a YAML file defines.

## Delete

Delete a resource:

```bash
pragma resources delete pragmatiks/gcp/storage/my-bucket
```

Delete all resources defined in a YAML file:

```bash
pragma resources delete -f myresources.yaml
```

This reads the provider, resource, and name from each document in the YAML file and deletes the matching resources.

Preview what a delete reaches without changing anything:

```bash
pragma resources delete --dry-run pragmatiks/pragma/secret/api-key
```

```text
Dry run — pragmatiks/pragma/secret/api-key was not removed.
Resources this reaches:
  pragmatiks/pragma/secret/api-key — torn down
  pragmatiks/agno/anthropic-model/claude — failed, its dependency is deleted
```

Each dependent listed as `failed, its dependency is deleted` waits while the delete runs and moves to `failed` once the resource is deleted; apply it again to retry it, or deactivate it to discard it. Add `--wait` to block until the delete finishes (`--wait-timeout <seconds>`, `0` waits forever).
