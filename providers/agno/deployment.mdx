> Deploys one or more Agno agents and teams as a Kubernetes Deployment with a Service, providing a REST API endpoint.

## `agno/runner`

The runner is the **only Agno resource that creates infrastructure**. It deploys a set of agents and teams into a single containerized service on Kubernetes.

### Config

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `agents` | `list[Dependency]` | Conditional | `[]` | References to `agno/agent` resources. At least one agent or team is required |
| `teams` | `list[Dependency]` | Conditional | `[]` | References to `agno/team` resources. At least one agent or team is required |
| `config` | `Dependency` | **Yes** | — | Reference to `kubernetes/config` providing cluster access (immutable) |
| `namespace` | `Dependency` | **Yes** | — | Reference to `kubernetes/namespace` the runner is deployed into (immutable) |
| `replicas` | `integer` | No | `1` | Number of pod replicas |
| `image` | `string` | No | `"ghcr.io/pragmatiks/agno-runner:v2"` | Container image for running the agents and teams |
| `security_key` | `string` | No | — | Bearer token for API authentication |
| `jwt_verification_key` | `string` | No | — | Public key for JWT-based authentication |
| `public` | `boolean` | No | `false` | Expose via LoadBalancer (true) or ClusterIP (false) |
| `cpu` | `string` | No | `"200m"` | CPU resource request |
| `memory` | `string` | No | `"1Gi"` | Memory resource request and limit |

### Outputs

| Field | Type | Description |
|-------|------|-------------|
| `spec` | `object` | Runner specification with deployment details |
| `url` | `string` | In-cluster service URL (`http://agno-<name>.<namespace>.svc.cluster.local`) |
| `ready` | `boolean` | Whether the runner is ready and serving |

## Dependencies

**Depends on:**
- `agno/agent` and/or `agno/team` (at least one required) — the agents and teams to deploy
- `kubernetes/config` (required) — access to the target cluster
- `kubernetes/namespace` (required) — namespace for the runner

**Depended on by:** Nothing — this is typically a leaf resource.

## Example — Deploy an agent

```yaml
provider: agno
resource: runner
name: my-agent
config:
  agents:
    - provider: agno
      resource: agent
      name: assistant
  config:
    provider: kubernetes
    resource: config
    name: my-cluster
  namespace:
    provider: kubernetes
    resource: namespace
    name: agents
  replicas: 2
  public: false
  cpu: "500m"
  memory: "2Gi"
```

## Example — Deploy a team with authentication

```yaml
provider: agno
resource: runner
name: research-team
config:
  teams:
    - provider: agno
      resource: team
      name: research-team
  config:
    provider: kubernetes
    resource: config
    name: my-cluster
  namespace:
    provider: kubernetes
    resource: namespace
    name: agents
  security_key: "my-secret-key"
  public: true
```

## Authentication

The runner supports two authentication modes:

| Mode | Config Field | Use Case |
|------|-------------|----------|
| **Bearer token** | `security_key` | Simple authentication for development |
| **JWT** | `jwt_verification_key` | Production authentication with RBAC |

When `jwt_verification_key` is set, it takes priority over `security_key`.

## Notes

- Provide at least one entry in `agents` or `teams`. Agent names must be unique within `agents`, and team names unique within `teams`.
- The `config` and `namespace` fields are **immutable** — changing them requires deleting and recreating the runner.
- The runner creates a Kubernetes Deployment and Service named `agno-<name>`. These are automatically managed.
- Create and update wait until the Deployment's replicas are ready.
- When `public: true`, a LoadBalancer Service is created, providing an external IP. Otherwise, the service is only accessible within the cluster.
- The container receives the combined agent and team specs and reconstructs every agent and team at startup.
- The runner includes health checks (startup, liveness, readiness probes) on `/health`.
